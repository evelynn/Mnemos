## 결론 먼저

**그렇다 — 직전까지 보고한 ~9.1 은 낙관적으로 부풀려졌다.** 루브릭에 맞춰
보수적으로 재채점하면 **≈ 8.5 / 10**. 약 **0.5~0.6 과대평가**였다.

부풀림의 원인(정직하게):
1. **루브릭 오용** — 9~10 은 "모범사례+테스트+문서+edge / 업계상위"인데, 한계가
   분명한(bounded/inferred) 기능에 9.5~9.6 을 매겼다. 예: 에이전트 추출은
   *파일 샘플 한정 + `certainty=inferred` + 단일파일(파일간 호출그래프 없음)* —
   이는 "핵심 작동(8)"이지 "업계상위(9.5)"가 아니다.
2. **미검증 이월** — D(보안)·F(그래프)·B 일부를 이번 세션에 독립 재검증 없이
   score-evidence 수치로 이월하면서 점수를 유지/상향.
3. **증분 누적** — 매 라운드 +0.1~0.2 씩 올리며 총합을 엄밀히 재산출하지 않음.

## 무엇이 "진짜"이고 무엇이 "부풀림"이었나

**진짜(검증됨, 부풀림 아님)** — 기능 자체와 게이트는 실측이다:
- 라이브 검증: C++ 추출, SQL 스키마 추출, trace_flow(자동수집), /ask 자가-심화,
  GUI Ask/trace 탭, 테이블 L1 요약, Plan/Diff 라이프사이클, OTLP 인제스트.
- 게이트(매 라운드 실측): ruff 0, pytest 1478 pass / 6 fail(전부 기존 환경),
  mypy 69, boot OK.

**부풀림(정정 대상)** — 그 기능들에 매긴 *영역 점수(9.5~9.6)와 9.1 평균*. 보수
재채점 시 대부분 8.4~8.8(핵심+일관 UX 수준)이지 9.5(모범사례+업계상위)가 아니다.

  파일간 호출그래프), D 보안 재감사, F 그래프 품질 측정.
